# Происхождение seed pool

Каталог предназначен для стартового пула вопросов (seed pool), из которого после перекладки идентификаторов формируется часть черновиков для разметки эталонной выборки $G$. Сами файлы seed pool и таблица соответствия идентификаторов будут скопированы сюда позже, после перекладки `warc_id → webpage_id`; на момент написания каталог содержит только этот документ.

## Источник

Два файла из репозитория промышленной системы «Chinese Media Analysis» (`ivran-lab/chinese-media`, ветка `prod`):

- `production/backend/rag/EN_rag_questions.json`
- `production/backend/rag/RU_rag_questions.json`

Каждый файл — JSON-объект вида `{"<вопрос>": "<warc_id>"}`: ключ — текст вопроса, значение — имя файла записи WARC с машинным переводом статьи, по которой вопрос сгенерирован. Файлы EN и RU содержат один и тот же набор вопросов на двух языках (английский и русский переводы одних и тех же черновиков), одинаковый порядок и одинаковые значения `warc_id`.

Формат значения: `trans_txt_<netloc>-<YYYY-MM>.warc_record_<N>.txt`, где `netloc` — домен издания, `YYYY-MM` — месяц выгрузки WARC, `N` — порядковый номер записи внутри архива.

## Почему seed pool не является эталонной выборкой

1. **Нет эталонных ответов.** Записи содержат только вопрос и идентификатор статьи; ни канонического ответа $A^*_i$, ни алиасов, ни evidence span нет. Из метрик $M$ по этим данным вычислимы только метрики поиска (попал ли документ в выдачу), но не метрики правильности ответа.
2. **Ключ `warc_id` не является стабильным идентификатором.** Имя файла кодирует домен, месяц и порядковый номер записи внутри WARC; в таблице `webmedia.webpages` нет колонки с именем файла, поэтому прямого соответствия `warc_id → webpage_id` нет, и связь приходится восстанавливать косвенно (см. план перекладки ниже). Схема записи $G$ требует стабильных ключей `webpage_id`, `urn_uuid`, `uri`.
3. **Неполное покрытие корпусом.** По оценке разведки, лишь около 67 % статей seed pool удаётся сопоставить с текущим снимком корпуса и индексом Qdrant; для остальных документ либо отсутствует, либо не идентифицируется однозначно. Для $G$ требуется покрытие 1 по построению ($S^*_i \subset \mathcal{I}$ и присутствует в Qdrant).
4. **Нет признака инвариантности во времени.** Вопросы не проверялись правилами $E_1$–$E_5$; значительная их часть — оценочные и прогнозные («как X оценивает…», «какие последствия может иметь…», «как это повлияет на…»), то есть заведомо не удовлетворяют $\mathrm{Inv}(q)$.
5. **Узкое покрытие.** Три домена и три календарных месяца (2022-06, 2023-04, 2023-05) против требования не менее 12 месяцев охвата; нет источников КНР и Сингапура.
6. **Дефекты формулировок.** Непереведённые фрагменты (английские названия должностей и программ внутри русских вопросов, русские слова внутри английских), составные вопросы из двух подвопросов, отсутствие дат-якорей.

Поэтому seed pool используется только как источник **черновиков**: каждый вопрос проходит ту же процедуру, что и вновь сгенерированные черновики (проверка $E_1$–$E_5$, добавление даты-якоря, формирование канонического ответа и $S^*$, разметка $R = 3$ аннотаторами). Ссылка на исходный вопрос сохраняется в поле `provenance.seed_pool_ref` записи $G$.

## План перекладки `warc_id → webpage_id / urn_uuid / uri`

1. Из `warc_id` извлечь `netloc` и месяц `YYYY-MM` регулярным выражением `^trans_txt_(?P<netloc>.+)-(?P<month>\d{4}-\d{2})\.warc_record_(?P<n>\d+)\.txt$`.
2. В таблице `webmedia.webpages` (колонки `id`, `uri`, `urn_uuid`, `text_content`, `text_content_trafilatura`, `date_time`, `netloc`, `lang_code`) отобрать кандидатов по условию `netloc = <netloc>` и `date_time` в пределах месяца `<month>` (с допуском ± 1 месяц на границах, поскольку месяц WARC — месяц выгрузки, а не публикации).
3. Среди кандидатов найти документ по совпадению текста: нормализованный префикс машинного перевода из файла записи WARC (первые 200–300 символов) сопоставляется с переводом документа в корпусе; при отсутствии перевода в таблице — по совпадению оригинала после обратного сопоставления через `urn_uuid` записи WARC (`WARC-Record-ID`).
4. Результат записать в `data/seed_pool/warc_to_webpage.csv` со столбцами `warc_id, webpage_id, urn_uuid, uri, published_at, netloc, match_method, match_score, in_qdrant`; неоднозначные и ненайденные соответствия — с пустым `webpage_id` и пометкой в `match_method`.
5. В seed pool для черновиков включаются только вопросы с однозначным соответствием и `in_qdrant = true`; остальные фиксируются в этом документе как потери с указанием причины.
