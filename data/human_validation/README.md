# Человеческая оценка ответов систем

Каталог для данных этапа валидации метрик: человеческие оценки $h^{(r)}_{i,f} \in \{0, \dots, 5\}$ ответов систем на подмножестве $G_h \subset G^+$. По этим оценкам отбирается валидированное подсемейство метрик $M' = \{m_k \in M : \rho_S(m_k, \bar h) \ge \rho_{\min}\}$, $\rho_{\min} = 0{,}5$, где $\bar h_{i,f}$ — среднее оценок трёх аннотаторов, $\rho_S$ — коэффициент корреляции Спирмена с 95%-м бутстреп-интервалом по вопросам. Проверяется гипотеза $H_4$: $\rho_S(m_J^{\text{corr}}, \bar h) \ge 0{,}5$ и $\alpha_{\text{human}} \ge 0{,}67$. Шкалы оценки описаны в [`docs/annotation_guidelines.md`](../../docs/annotation_guidelines.md), раздел 11.

## Объём

- $n_h = 100$ вопросов из $G^+$ (версия `v1.0`, split `test`), отобранных стратифицированно по `category`, `source` и `difficulty`.
- Три системы $\mathcal{H}_h = \{f_{\text{prod}},\ f_0^{(m_1)},\ f_\rho^{(m_1)}\}$: промышленная система, открытая модель $m_1$ без поиска и та же модель с выдачей промышленного ретривера. Конкретная $m_1$ фиксируется в `docs/systems.md` до начала оценки.
- $R = 3$ аннотатора; каждый оценивает все $100 \times 3 = 300$ пар «вопрос — ответ системы»; всего 900 пар оценок по двум шкалам.
- Ориентировочно 2 минуты на пару — около 10 часов на аннотатора.

## Файлы

| Файл | Содержание | Публикуется |
|---|---|---|
| `items.jsonl` | Оцениваемые пары в обезличенном виде (одна запись на вопрос) | да |
| `ratings_r1.csv`, `ratings_r2.csv`, `ratings_r3.csv` | Оценки аннотаторов `r1`, `r2`, `r3` | да, после заморозки |
| `system_blinding.csv` | Соответствие `item_id, blind_label, system_id` | да, после заморозки оценок |
| `agreement.json` | Krippendorff $\alpha$ (порядковая метрика) и попарные корреляции Спирмена между аннотаторами по каждой шкале | да |
| `metric_vs_human.csv` | $\rho_S(m_k, \bar h)$ с бутстреп-интервалами для каждой метрики $m_k \in M$ | да |

### `items.jsonl`

Одна запись на вопрос $q_i \in G_h$:

```json
{"item_id": "gs-0001", "question_ru": "…", "answer_canonical": "…", "answer_aliases": ["…"], "supporting_docs": [{"webpage_id": 1234567, "uri": "https://…", "published_at": "2024-11-08", "evidence_span_ru": "…"}], "outputs": [{"blind_label": "S1", "answer_text": "…", "citations": [1, 2], "source_map": {"1": {"webpage_id": 1234567, "uri": "https://…"}, "2": {"webpage_id": 2345678, "uri": "https://…"}}, "is_refusal": false}, {"blind_label": "S2", "…": "…"}, {"blind_label": "S3", "…": "…"}]}
```

Поле `item_id` совпадает с `id` записи в `data/golden_set/v1.0/golden_set.jsonl`. Метки `blind_label` (`S1`, `S2`, `S3`) присваиваются системам случайно и независимо для каждого вопроса; порядок предъявления вопросов также перемешан для каждого аннотатора (зерно генератора фиксируется в `system_blinding.csv`). Тексты ответов приводятся дословно, включая инлайн-цитаты `(N)`; `source_map` даёт аннотатору доступ к процитированным документам.

### `ratings_r{1,2,3}.csv`

UTF-8, разделитель — запятая, кавычки по RFC 4180, первая строка — заголовок. Ровно 300 строк данных на файл (100 вопросов × 3 системы).

| Столбец | Тип | Значения |
|---|---|---|
| `item_id` | строка | `id` записи $G$ |
| `system_id` | строка | Идентификатор системы после снятия ослепления (`prod`, `m1-closed`, `m1-rag` — как в `docs/systems.md`); в рабочих файлах аннотаторов на этом месте стоит `blind_label` |
| `correctness_0_5` | целое 0–5 | Правильность относительно $A^*_i$ |
| `groundedness_0_5` | целое 0–5 или пусто | Обоснованность; пусто (NA) для отказов «Я не знаю.» |
| `comment` | строка | Свободный комментарий (может быть пустым) |

Пример:

```csv
item_id,system_id,correctness_0_5,groundedness_0_5,comment
gs-0001,prod,5,4,"ссылка (2) стоит у второго предложения, а подтверждает первое"
gs-0001,m1-closed,3,,"отказа нет, источники не приведены — обоснованность 0"
gs-0001,m1-rag,0,,"отказ при ответимом вопросе"
```

В примере вторая строка иллюстрирует типичную ошибку: при содержательном ответе без источников обоснованность равна 0, а не NA; пустое значение допустимо только при `is_refusal = true`.

## Обезличивание

- Аннотаторы обозначаются `r1`, `r2`, `r3`; соответствие реальным лицам и идентификаторам `A1`–`A3` из разметки эталонной выборки хранится вне репозитория.
- До заморозки оценок аннотаторы не знают, какая система стоит за `blind_label`, и не видят оценок друг друга.
- `system_blinding.csv` публикуется одновременно с `ratings_r{1,2,3}.csv`; после публикации оценки не редактируются.

## Порядок обработки

1. Собрать ответы трёх систем на $G_h$ (temperature 0, фиксированный seed, поле `model` каждого ответа записано) → `items.jsonl` с ослеплением.
2. Три независимых раунда оценки → рабочие файлы аннотаторов.
3. Снять ослепление, проверить полноту (300 строк, допустимые значения), заморозить `ratings_r{1,2,3}.csv`.
4. Вычислить $\alpha_{\text{human}}$ и попарные корреляции → `agreement.json`; среднее попарное согласие людей — потолок для $\rho_S(m_k, \bar h)$.
5. Вычислить $\bar h_{i,f}$, затем $\rho_S(m_k, \bar h)$ с 95%-м бутстреп-интервалом ($B = 10^4$) для каждой $m_k \in M$ → `metric_vs_human.csv`; отобрать $M'$ по порогу $\rho_{\min} = 0{,}5$. Детерминированные метрики без человеческого аналога (Recall@k и т. п.) включаются в $M'$ напрямую.
6. Отдельно проверить самопредпочтение судьи-LLM ($H_5$): сравнить $\rho_S$ и средний сдвиг оценок судьи для ответов модели, совпадающей с моделью судьи, против остальных.
