# Оцениваемые системы

Документ фиксирует состав оцениваемого подмножества $`\mathcal{H}_{\text{eval}}`$, условия работы провайдера моделей и требования к судье. Обозначения — как в [problem_statement.md](problem_statement.md). Конфигурации систем лежат в [`code/configs/systems/`](../code/configs/systems/), судьи — в [`code/configs/judge.yaml`](../code/configs/judge.yaml).

## 1. Состав $`\mathcal{H}_{\text{eval}}`$

```math
\mathcal{H}_{\text{eval}}=\{f_{\text{prod}}\}\cup\{f_0^{(m)}\}_{m\in\mathcal{L}}\cup\{f_\rho^{(m)}\}_{m\in\mathcal{L}},\qquad |\mathcal{H}_{\text{eval}}|=1+2|\mathcal{L}|=13.
```

| Обозначение | Ретривер | Генератор | Что измеряет сравнение |
|---|---|---|---|
| $`f_{\text{prod}}`$ | $`\rho_{\text{prod}}`$: Qdrant + SearchAPI | $`g_{\theta_{\text{prod}}}`$ — генератор промышленной системы | качество промышленной системы как она развёрнута |
| $`f_\rho^{(m)}`$, $`m\in\mathcal{L}`$ | $`\rho_{\text{prod}}`$, выдача кэшируется и одинакова для всех $`m`$ | $`g_m`$ | вклад модели-генератора при фиксированном поиске (абляция «модель против ретривера») |
| $`f_0^{(m)}`$, $`m\in\mathcal{L}`$ | нет ($`\hat S=\varnothing`$) | $`g_m`$ | «закрытая книга»: что модель знает без корпуса; мера утечки знаний из предобучения |

## 2. Промышленная система $`f_{\text{prod}}`$

Объект исследования — система «Chinese Media Analysis» (репозиторий `ivran-lab/chinese-media`, ИВ РАН), описанная в статье Багров А. М. и др., 2026 (Проблемы Дальнего Востока, № 1, DOI 10.7868/S2712909826010109). Состояние на 2026-09-17 (ветка `prod`, коммит `82a38c0`):

| Компонент | Реализация |
|---|---|
| Корпус | китайскоязычные СМИ КНР, Тайваня, Гонконга, Сингапура; метаданные в PostgreSQL `webmedia.webpages` (`webpage_id`, `urn_uuid`, `uri`, дата, `lang_code`) |
| Индекс | Qdrant, коллекция `webmedia_sentence_transformers_distiluse_base_multilingual_cased_v2`, 23,9 млн точек, вектор 512; идентификатор точки — `webpage_id << 16 \| chunk_number`; в payload — предпосчитанный русский перевод чанка |
| Эмбеддинги | `distiluse-base-multilingual-cased-v2` (SentenceTransformers), поиск плотный, без BM25 и реранкера |
| Переписывание запроса | промпт `translate_model.txt`: чистка русского запроса и перевод на язык поиска |
| Retrieval | `query_points(limit=k, score_threshold)`, дедупликация до $`m`$ уникальных `webpage_id`, подгрузка полных текстов из PostgreSQL; параметры прогона оценки: $`k=5`$, $`m=3`$, порог $`0.3`$ |
| Deep search | опционально — Selenium-скрапер SearchAPI по 141 домену китайских СМИ (`sapi_domains_MODIFIABLE.json`); в режиме $`f_{\text{prod}}`$ включён с `num_docs=1` |
| Генерация | OpenAI-совместимый API провайдера ИВ РАН (llama-swap): `IVRAN_LLM_BASE_URL`, `IVRAN_LLM_MODEL`; системный промпт `result_model.txt` требует ответ на русском, инлайн-цитаты `(N)` по нумерованным источникам и ровно «Я не знаю.» при недостатке данных |
| Выход | `POST /rag_translate` (JSON) — используется прогонами; ответ содержит текст, `metadata_list[*].url` и `source_map[N] = {url, netloc}`; цитаты извлекаются регулярным выражением по маркерам `(N)` и отображаются в `webpage_id` |

Для метрик $`\hat S`$ формируется из номеров $`(N)`$, реально встретившихся в тексте ответа, а не из всего списка найденных документов; `retrieved_ids` (ранжированная выдача $`\rho_{\text{prod}}`$) сохраняется отдельно для метрик поиска.

## 3. Провайдер моделей и множество $`\mathcal{L}`$

Провайдер — llama-swap на сервере ИВ РАН, доступ по SSH-туннелю или VPN. Снимок `/v1/models` от 2026-09-04 (`production/docs/research/model-windows-and-tokens.md` в репозитории объекта):

| Идентификатор у провайдера | Окно контекста | Решение | Основание |
|---|---|---|---|
| `DeepSeek-R1-Distill-Qwen-32B-Q5_K_M` | 32 768 (замерено) | $`\in\mathcal{L}`$ | reasoning-модель; фактически обслуживает промышленную систему (см. §4) |
| `unsloth/Qwen3.6-27B-MTP-GGUF:UD-Q4_K_XL` | 65 536 (замерено) | $`\in\mathcal{L}`$ как «Qwen3.6-27B» | основная квантизация; вторая квантизация `Qwen3.6-27B-Q6_K` — резерв для проверки чувствительности к квантизации, в основную таблицу не входит |
| `Qwen3.8-27B` | не замерено | $`\in\mathcal{L}`$ | новейшее поколение семейства |
| `GLM-4.1V-9B-Thinking-BF16` | не замерено | $`\in\mathcal{L}`$ | китайское семейство вне Qwen; малый размер — нижняя граница |
| `GigaChat-20B-A3B-instruct-v1.5-q8_0` | не замерено | $`\in\mathcal{L}`$ | российская модель; проверка русскоязычной генерации |
| `Qwen-AgentWorld-35B-A3B` | не замерено | $`\in\mathcal{L}`$ | MoE-вариант Qwen |
| `Hy-MT2-30B-A3B-Q4_K_M` | не замерено | исключена | модель машинного перевода, не вопросно-ответная |
| `Laguna-XS-2.1-Q4_K_M` | не замерено | исключена | малая модель без документированных бенчмарков по китайскому |
| `Qwen3-Coder-30B-A3B-Instruct-UD-Q5_K_XL` | не замерено | исключена | специализация на коде |

Итого $`|\mathcal{L}|=6`$. Состав фиксируется до прогонов; замена модели оформляется записью в [decisions.md](decisions.md) и новой версией конфигурации.

Единые условия генерации для всех $`f\in\mathcal{H}_{\text{eval}}`$: temperature $`0`$, фиксированный seed, один ответ на вопрос, максимальная длина ответа одинакова; для reasoning-моделей блок рассуждений (`<think>…</think>`) отбрасывается до вычисления метрик. Промпт для $`f_\rho^{(m)}`$ — тот же `result_model.txt`, что у $`f_{\text{prod}}`$; для $`f_0^{(m)}`$ — тот же промпт без блока контекста и без требования цитировать, но с сохранённым правилом отказа «Я не знаю.». Версии промптов фиксируются полем `prompt_version` и хешем.

## 4. Известный дефект провайдера и требование fail-fast

Модель по умолчанию промышленной системы `IVRAN_LLM_MODEL=Qwen/Qwen3.5-9B` в снимке `/v1/models` от 2026-09-04 отсутствует. Клиент промышленной системы при неизвестном идентификаторе молча берёт первую модель списка, поэтому фактически запросы обслуживает `DeepSeek-R1-Distill-Qwen-32B-Q5_K_M`; подмена не видна ни в интерфейсе, ни в логах. Для эксперимента это означает:

1. Идентификатор каждой модели проверяется по `/v1/models` до прогона; при отсутствии — прогон прерывается с ошибкой (`fail_fast_on_unknown_model: true` в конфигурациях).
2. Для каждого ответа сохраняется фактическое поле `model` из ответа API (`model_reported`); в таблице результатов публикуется именно оно (`model_id_reported`).
3. Снимок `/v1/models` записывается в `meta.json` прогона.
4. Для $`f_{\text{prod}}`$ генератор $`g_{\theta_{\text{prod}}}`$ определяется по факту, а не по конфигурации; если к моменту прогонов конфигурация промышленной системы изменится, фиксируется новое значение.

## 5. Судья

Судья реализует $`m_J^{\text{corr}}`$, семь измерений $`m_J^{(d)}`$ и, при выборе NLI-варианта через LLM, $`\mathrm{CP}_{\text{ent}}`$.

Требования (ограничение 4 постановки, предположение о независимости судьи):

- судья $`\notin\mathcal{L}\cup\{g_{\theta_{\text{prod}}}\}`$; поскольку $`g_{\theta_{\text{prod}}}`$ фактически совпадает с DeepSeek-R1-Distill-Qwen-32B $`\in\mathcal{L}`$, ни одна модель из §3, включённая в $`\mathcal{L}`$, судьёй быть не может;
- допустимые варианты: (а) модель провайдера, не входящая в $`\mathcal{L}`$ и не специализированная — на 2026-09-04 такой нет; (б) вторая квантизация `Qwen3.6-27B-Q6_K` — недопустима, так как это то же семейство, что и член $`\mathcal{L}`$ (самопредпочтение распространяется на семейство); (в) внешняя модель через отдельный API — допустима при согласовании с ИВ РАН передачи вопросов и ответов (тексты корпуса судье не передаются, только evidence-span); (г) ансамбль двух судей из разных семейств с флагом расхождения;
- temperature $`0`$, строгий JSON-контракт, `n_samples: 1` в основном прогоне; отчёт о воспроизводимости — повторный прогон на подвыборке из 50 ответов;
- проверка самопредпочтения ($`H_5`$): на $`G_h`$ сравнивается $`\rho_S(m_J^{\text{corr}},\bar h)`$ отдельно на ответах систем семейства судьи и остальных; различие оценивается бутстрепом.

Окончательный выбор судьи — декабрь 2026, запись в [decisions.md](decisions.md).

## 6. Расхождение моделей в артефактах предыдущей работы

| Артефакт | Указанная модель генерации |

| Презентация (декабрь 2025) | YandexGPT |
| Транскрипты сеансов (октябрь–декабрь 2025, март 2026) | `qwen3-235b-a22b-fp8` через Yandex Cloud |
| Код, ветка `prod` (сентябрь 2026) | `Qwen/Qwen3.5-9B` в конфигурации; фактически DeepSeek-R1-Distill-Qwen-32B |

Расхождение — само по себе аргумент в пользу протокола §4: без записи фактической модели результаты не воспроизводимы. В тексте работы генератор $`f_{\text{prod}}`$ указывается по полю `model` прогона.

## 7. Соответствие конфигурациям

| Файл | Система | Ключевые поля |
|---|---|---|
| `code/configs/systems/prod.yaml` | $`f_{\text{prod}}`$ | `kind: prod_api`, `retriever: qdrant+searchapi`, `k: 5`, `m: 3`, `threshold: 0.3`, `temperature: 0.0`, `fail_fast_on_unknown_model: true` |
| `code/configs/systems/open_with_retrieval.yaml` | $`f_\rho^{(m)}`$ | `kind: openai_compat`, `retriever: cached_prod`, `model_id: <из §3>` |
